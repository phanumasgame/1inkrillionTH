# Krillion TH

เกมพิมพ์คำตอบฉบับไทยที่ได้แรงบันดาลใจจาก Krillion.io เล่นในเบราว์เซอร์ได้โดยไม่ต้องมีเซิร์ฟเวอร์หรือบัญชีผู้เล่น

## สถานะข้อมูล

คลังเวอร์ชัน `1.0.13` ใช้ระบบคิดคะแนนแบบผสม (**236 โจทย์**: เรื่องไทย 118 ข้อ และเรื่องทั่วไป 118 ข้อ) มีคำตอบที่คิดคะแนนได้รวม **391,522 รายการ** (21–15,000 รายการต่อข้อ) แบ่งเป็น **6 โจทย์จากผลสำรวจที่เผยแพร่จริง** (ไทย 5, ทั่วไป 1) และ **230 โจทย์จัดระดับความคุ้นเคยเชิงบรรณาธิการ** (Curated Familiarity; ไทย 113, ทั่วไป 117) ในจำนวนนี้ **228 โจทย์มีคำตอบตั้งแต่ 100 รายการขึ้นไป**, **154 โจทย์มีคำตอบหลักพัน (1,000–15,000 รายการ)** และ **16 โจทย์มีคำตอบระดับหลักหมื่น (10,500–15,000 รายการต่อข้อ)** พร้อมระบบ **Share Card Studio** บันทึกและคัดลอกผลเป็นรูปการ์ด `.PNG` และฉากหลังใต้ทะเลที่ยิ่งดำลึกยิ่งพบสิ่งมีชีวิตและปรากฏการณ์ใต้สมุทรมากขึ้น

โจทย์ฉบับร่างเดิม 100 ข้อและ 3,705 คำตอบยังเก็บไว้ใน `data/questions.json` เพื่อใช้อ้างอิงและตรวจความสมบูรณ์ย้อนหลัง แต่ไม่ได้ใช้เล่นโดยตรงและไม่รวมใน static build

แหล่งข้อมูลที่ใช้และเกณฑ์การจัดระดับของแต่ละชุดบันทึกอยู่ใน `data/survey-bank.json` (ดูได้ในหน้า "ที่มาของตัวเลข" และ "เกี่ยวกับ" ภายในเกม) รวมถึง [บันทึกการค้นคว้า](docs/survey-research.md) หน้าเฉลยค้นคำตอบด้วยชื่อหรือชื่อเรียกอื่นได้ทีละ 100 รายการและเปิดดูที่มาของตัวเลขหรือคำอธิบายการจัดระดับได้ชัดเจนทุกข้อ

## กติกาคะแนน

ในแต่ละข้อ นำ **ค่าที่วัดจากผลสำรวจ** มาเรียงจากมากไปน้อย แล้วกระจายอันดับลงห้าระดับ Plankton 10, Schooler 30, Rare 60, Deep Cut 85 และ One in a Krillion 100 คะแนน ค่าที่เท่ากันได้แต้มเท่ากันและอาจไม่มีคำตอบในบางระดับ ตัวเลขอาจเป็นร้อยละที่รายงาน ร้อยละที่คำนวณจากข้อมูลจริงพร้อมตัวหาร หรือค่าเฉลี่ยบนสเกลแบบสอบถาม คะแนนหนึ่งแต้มเท่ากับความลึก 10 เมตร

คะแนนเป็นวิธีแปลงอันดับสำหรับเกมเท่านั้น ไม่ใช่ความน่าจะเป็นหรือจำนวนผู้ตอบ และใช้เปรียบเทียบเฉพาะคำตอบที่รายงานเปิดเผยเท่านั้น รายการที่ไม่ได้เปิดเผยไม่ได้หมายความว่าไม่มีคนตอบ จึงไม่ให้คะแนนรายการดังกล่าว การข้ามหรือหมดเวลาได้ 0 แต้ม

ผลสำรวจบางแห่งใช้คำตอบแบบจัดกลุ่มหรืออนุญาตเลือกหลายข้อ กลุ่มและฐานตัวอย่างของแต่ละรายงานต่างกัน ตัวอย่างรวมที่ระบุอาจไม่ใช่ฐานย่อยของทุกคำถาม คลังนี้เก็บข้อจำกัดดังกล่าวไว้พร้อมข้อมูล ไม่คำนวณจำนวนผู้ตอบย้อนกลับจากร้อยละปัดเศษ

## เริ่มเล่นในเครื่อง

ต้องใช้ Node.js 22 ขึ้นไป ไม่มี dependencies ภายนอก

    npm run dev

เปิด http://127.0.0.1:4173 หรือกำหนดพอร์ตบน PowerShell ด้วย `$env:PORT = '4174'` ก่อนรัน หยุดเซิร์ฟเวอร์ด้วย Ctrl+C

Daily และ Endless มีรอบละ 7 ข้อ ข้อละ 25 วินาที พร้อมช่วงอ่านโจทย์ 3 วินาที เป็นเกมพิมพ์ตอบ มีตัวอย่างหนึ่งรายการเมื่อยังนึกไม่ออก เกมใช้ชื่อเรียกที่คัดไว้และเสนอคำแก้เมื่อสะกดใกล้เคียง คำที่ไม่อยู่ในรายการที่แหล่งเผยแพร่สามารถแก้แล้วลองใหม่ได้ก่อนหมดเวลา

ผล การตั้งค่า และตัวละครเก็บใน localStorage ของเบราว์เซอร์ ปฏิทิน Daily ใช้ America/New_York ตามต้นแบบ ประวัติคะแนนรุ่นก่อนที่ใช้การประเมินยังเก็บในเครื่อง แต่ไม่นำมารวมกับสถิติจากโพล และไม่เปิดให้เล่นต่อด้วยคะแนนเดิม

## ตรวจสอบ

    npm test
    npm run check
    npm run build
    npm run preview

Preview ของ static build เปิดที่ http://127.0.0.1:4174 โดยปริยาย `check` ตรวจรูปแบบ ข้อมูลที่จำเป็น (ทั้งข้อมูลผลสำรวจและข้อมูลจัดระดับความคุ้นเคย) และขั้นต่ำ 21 คำตอบต่อข้อของคลังเวอร์ชัน `1.0.13` รวมถึงตรวจโครงสร้างฉบับร่างเดิมด้วย การตรวจอัตโนมัติไม่สามารถยืนยันความถูกต้องหรือสิทธิ์ของแหล่งข้อมูลภายนอกแทนการอ่านต้นฉบับได้

## Vercel, ฐานข้อมูล (Neon Postgres) และระบบ Survey

`vercel.json` รัน `npm run build` เพื่อสร้างไฟล์หน้าเว็บใน `dist/` และเผยแพร่ Vercel Serverless Functions จาก `api/`:

- **Survey หลังเล่นเสร็จ**: บนหน้าสรุปผล (และในหน้า Field notes รายข้อ) มีปุ่ม **เสนอคำตอบที่ควรมีเพิ่มในคลัง (SURVEY)** พร้อมปุ่มลัดเติมคำที่ผู้เล่นลองพิมพ์ในรอบนั้นแล้วยังไม่พบในคลัง
- **API Endpoints**:
  - `POST /api/suggestions` — บันทึกคำตอบที่ผู้เล่นเสนอลงตาราง `answer_suggestions`
  - `POST /api/telemetry` — บันทึกสรุปรอบเล่น (`dive_sessions`, `round_attempts`) และคำที่พิมพ์แล้วไม่พบในคลัง (`rejected_guesses`) แบบไม่ระบุตัวตน
  - `GET /api/suggestions?view=summary|raw|rejected|questions&format=json|csv` — ดึงข้อมูลสรุปหรือ Export CSV (ป้องกันด้วย `ADMIN_TOKEN` ผ่าน `Authorization: Bearer <ADMIN_TOKEN>`)
  - `GET /api/health` — ตรวจสถานะ API และการเชื่อมต่อฐานข้อมูล (`?check=db`)
- **Environment Variables** (บน Vercel และ `.env.local`):
  - `DATABASE_URL` — Connection string ของ Neon Postgres (เชื่อมต่ออัตโนมัติผ่าน Vercel Marketplace)
  - `ADMIN_TOKEN` — โทเคนสำหรับเรียกดู/Export ข้อมูลผ่าน `GET /api/suggestions`
- **สคริปต์ช่วยดูแลคลัง**:
  - `npm run db:init` — สร้างตารางและ index ในฐานข้อมูล
  - `npm run export-suggestions -- --view=summary --format=csv --out=outputs/analytics/suggestions.csv` — ส่งออกคำตอบที่ถูกเสนอหรือพิมพ์ไม่พบเป็น CSV (UTF-8 BOM เปิดภาษาไทยใน Excel ได้ทันที)

ข้อมูล `localStorage` ในเครื่องไม่ย้ายจาก localhost ไปยังโดเมน Vercel โดยอัตโนมัติ แต่คำตอบที่ผู้เล่นเสนอผ่าน Survey และสถิติรอบเล่นแบบไม่ระบุตัวตนจะเก็บไว้ในฐานข้อมูลของแอปเพื่อใช้วิเคราะห์และขยายคลังคำถามต่อไป สำหรับ Preview:

    npx --yes vercel deploy --environment preview

ตรวจ target และ Deployment Protection ก่อนแชร์ การเชื่อม GitHub กับ Vercel สำหรับ deploy อัตโนมัติเป็นการตั้งค่าแยก และการ push branch ที่เป็น production อาจกระตุ้น production deployment ได้

## เพิ่มโจทย์สำรวจ

1. หาแหล่งต้นทางที่ระบุผลสำรวจจริง คำถาม/ขอบเขต ตัวเลข กลุ่มประชากร ช่วงเวลา และขนาดตัวอย่างที่ตรวจสอบได้ ตรวจเงื่อนไขการนำข้อมูลไปใช้ด้วย
2. เพิ่มโจทย์ใน `data/survey-bank.json` ระบุผู้สำรวจ ลิงก์ HTTPS กลุ่มตัวอย่าง ขนาดตัวอย่าง และค่าที่วัดของแต่ละคำตอบ ถ้าคำนวณร้อยละจากข้อมูลที่เผยแพร่ให้ระบุวิธีและตัวหาร หากแหล่งวัดค่าเฉลี่ย 1–7 ให้ใช้ `rating` พร้อม `survey.scale` เป็น `rating-1-to-7`
3. โจทย์ปลายเปิดใหม่ให้มองหาอย่างน้อย 100 คำตอบที่แยกคะแนนได้ ตรวจว่า label และ aliases ตรงกับข้อมูล คำสะกดอื่นไม่นับเพิ่ม และหนึ่งกลุ่มที่ต้นทางวัดรวมยังเป็นหนึ่งรายการ
4. เพิ่มเวอร์ชันคลังและรัน `npm test`, `npm run check`, `npm run build` จากนั้นทดลองเล่นจริงพร้อมตรวจแหล่งอ้างอิง

`src/survey.js` ตรวจโครงสร้างและแยกคิดระดับอย่างโปร่งใส: ข้อที่มี `survey` คำนวณระดับจากตัวเลขที่เผยแพร่จริงทุกครั้ง ส่วนข้อที่มี `curated` ใช้ระดับความคุ้นเคยพร้อมคำอธิบายประกอบ (`reason` หรือ `curated.tierReasons`) โดยไม่ปนตัวเลขสำรวจปลอม `src/game.js` ดูแลกติกาและตัวจับเวลา ส่วน `src/storage.js` เก็บการอ้างอิงคลังแบบกระชับ (`$bankRef`) พร้อม fallback เพื่อไม่ให้เกินโควต้า `localStorage` เมื่อเล่นหมวดคำตอบหลักพัน

## ภาพ เสียง และงานศึกษา

ภาพฉากและตัวละครสร้างใหม่สำหรับโปรเจกต์ ดูรายละเอียดใน `assets/README.md` และ `assets/sources.json` เสียงสร้างด้วย Web Audio ชื่อแบรนด์และเสียงยังควรตรวจสิทธิ์ก่อนเผยแพร่ทั่วไป โปรเจกต์นี้ไม่ได้เป็นบริการของ Krillion.io

[รายงานวิเคราะห์ต้นฉบับ 500 ข้อ](docs/krillion-question-study.md) เป็นงานศึกษาก่อนเปลี่ยนระบบคะแนน ใช้โจทย์ย้อนหลังสาธารณะ 500 ข้อและทดลองเล่นต้นฉบับ 7 ข้อ ไม่ได้หมายความว่าทดลองเล่นต้นฉบับครบ 500 ข้อ
